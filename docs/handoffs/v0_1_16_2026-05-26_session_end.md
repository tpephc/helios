### 2.1 v2.1 Hotfix — Shioaji boundary normalization (`3cc7c0a`)

Post-deploy sim verification (2026-05-25) revealed two bugs in `LiveBroker`:

**Bug 1 — LOTS vs SHARES unit mismatch:**
`deal.quantity` in Shioaji Common path is in LOTS, not SHARES. v2 assumed SHARES,
so every fully-filled 1-lot order was classified PARTIAL.

**Bug 2 — `_resolve_stock_contract` used `in` operator on StreamMultiContract:**
`symbol in tse` always returned False because Shioaji `StreamMultiContract`
doesn't implement `__contains__`. Used `.get()` instead.

**Patches applied:**
| Patch | File | Change |
|---|---|---|
| P-δ-1 | `execution/order_types.py` | Add `OrderLot` enum |
| P-δ-2 | `execution/live_broker.py` | `_submit` × `SHARES_PER_LOT` at boundary |
| P-δ-2b | `execution/live_broker.py` | `_resolve_stock_contract` use `.get()` |
| P-δ-2c | `execution/live_broker.py` | `fetch_trades` × `SHARES_PER_LOT` |
| P-δ-2d | `execution/live_broker.py` | `fetch_holdings` × `SHARES_PER_LOT` |
| P-δ-3 | `execution/broker_adapter.py` | Protocol docstring corrected |
| P-δ-4 | `docs/design/execution_model.md` | §13 Boundary normalization |
| P-δ-5 | `docs/decision_records/` | Backlog updates |

**Design invariant (FROZEN):**
> Broker adapters may expose broker-native quantity semantics, but all
> persisted execution accounting inside Helios must use canonical share-equivalent units.

**Verification:**
- Unit arithmetic 4/4 pass

- `submit_buy` resolves contract correctly (broker_order_id=103BCC)

### 2.3 P-obs-1 scope reframe + backlog #15

**Key insight (2026-05-26):** 16:00 cron is NOT a full execution observation window.
It is an after-hours broker availability observation only.

Observable at 16:00 (after-hours):
- Shioaji login behavior
- `place_order` reachability
- Reject type (broker_reject vs transport)
- `order_journal` INTENT → FAILED/SUBMITTED transition

NOT observable at 16:00 (requires P-obs-2 intraday):
- `deal.quantity` unit on actual fill
- FILLED/PARTIAL path end-to-end
- Callback behavior
- `fetch_trades` filled payload

**Backlog #15:** decouple signal generation from broker submission window.
Current 16:00 `daily_run` conflates EOD signal scan with broker submission.

Required v0.1.17 design:
