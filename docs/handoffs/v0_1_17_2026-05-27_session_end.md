### 2.3 Step 3: execution_submitter (a04bc53)

- New script: `scripts/execution_submitter.py`
- Two modes: `--mode submit` (cron 08:30) and `--mode cancel` (cron 09:05)
- Submit flow:
  1. Filesystem flock (prevents double-run)
  2. Read `READY_FOR_SUBMISSION WHERE target_fill_date = today`
  3. Pre-submission checks (stale date, duplicate position, prev_close)
  4. `limit_price = prev_close * (1 + max_entry_gap_pct)` (INV-2)
  5. `update_order_spec` (limit_price + notional) while still READY_FOR_SUBMISSION
  6. `mark_submitted` (optimistic, before broker call)
  7. Shioaji login → contract → place_order (LMT ROD)
  8. Confirm: set `broker_order_id`, clear `requires_broker_verification`
- Cancel flow:
  1. Find SUBMITTED older than `cancel_after_minutes`
  2. Mark EXPIRED (Shioaji cancel API deferred — Q3 unverified)
  3. Expire leftover READY_FOR_SUBMISSION (missed window)
- Direct Shioaji API (not LiveBroker) — avoids record_intent conflict
- `update_order_spec` relaxed to accept READY_FOR_SUBMISSION state

**Design decisions:**
- No LiveBroker involvement — execution_submitter manages its own Shioaji session
- Idempotency: `mark_submitted` + `requires_broker_verification=True` before broker call;
  reconcile resolves crash-between-submit-and-confirm
- `max_entry_gap_pct = 0.03` [ASSUMED] until #16 calibrates
