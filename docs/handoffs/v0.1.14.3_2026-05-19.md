### v0.1.14.3.7 — Two production bugs fixed on 2026-05-18

**Bug A — Listener pre-startup queue pollution**

Scar: operator's prior-session "Approve" (silently ignored by v3.5 listener,
never confirmed to Telegram) sat in the getUpdates queue. New v3.6 listener
started with `offset=0`, received the stale message, `classify_command` resolved
it onto freshly-pushed DEV-TEST-003 → phantom approval the operator never sent.

Fix: `_drain_pre_startup_updates(bot)` called on listener entry.
- `get_updates(offset=-1, timeout=0)` → fetch last update without confirming
- `get_updates(offset=last_id+1, timeout=0)` → confirm-and-discard all
- Main loop enters with offset past any pre-startup messages
- Log event: `listener_drained_pre_startup`

Files changed: `communication/telegram/listener.py`

**Bug B — `_check_atr_drift` asymmetric "cannot verify" paths**

Scar: `_check_atr_drift` returned `(False, "...無法驗證漂移")` when
`daily_price_adj[fill_date]` had no row — i.e., every intraday approval before
EOD sync had run. The no-ATR path (same function, 3 lines above) returned
`(True, "...跳過...")`. Two "cannot verify" exits, opposite semantics; the
dangerous one (reject) fired on every trading day before ~15:00.

Fix: no-price path now returns `(True, "...跳過漂移檢查")` — symmetric with
no-ATR path and with `execution.expiry.expire_by_drift` (which also skips
when current_prices is empty).
- Log event: `approval_drift_check_skipped_no_price`

Files changed: `execution/approvals.py`

  integration test: `summary["approved"]==[]`, signal stays PENDING,

- `test_check_atr_drift_returns_true_when_no_price_data_for_fill_date` — pins

### v0.1.14.3.8 — `--bootstrap-price` flag

Scar: `PaperBroker.submit_buy` reads `daily_price_adj[fill_date]` for both
`adj_open` (ref_price) and `volume` (liquidity gate). Before EOD sync runs
(before ~15:00 Taipei), both checks fail → `paper_fill_failed: no_volume_data`.
The operator had to either wait hours or inject rows manually.

Fix: `scripts/dev_push_signal.py` new args:
- `--bootstrap-price`: calls `_bootstrap_price_row(ticker, fill_date, price, volume)`
  before pushing. Uses `INSERT OR REPLACE` → idempotent; EOD sync overwrites
  with real data.
- `--bootstrap-volume INT`: synthetic volume (default 25,000,000 shares).

`_bootstrap_price_row` sets `adj_open = adj_close = adj_high = adj_low = price`,
`cum_factor = 1.0`. Drift against itself is 0 → approval drift gate passes.

New test: `test_bootstrap_price_enables_broker_fill` — verifies fill fails before
bootstrap and succeeds after; checks `ref_price` within 1% of bootstrap price.

Test count: 73 → 74 passed.

## 8. Architecture Decisions (this session)

### Drain-first listener pattern
`listen_for_approvals` now always calls `_drain_pre_startup_updates(bot)` as
its first action. The function is a documented, testable unit — not inline logic.
Any future listener restart path (e.g., `run_listener_only.py`) MUST call
through `listen_for_approvals`, not bypass it, to inherit the drain guarantee.

### "Cannot verify" = permissive in approval path
Both no-ATR and no-price exits in `_check_atr_drift` return `(True, "...跳過...")`.
This is a deliberate policy: intraday approval before EOD sync is a normal
operating condition, not an error. The signal proceeds; the operator is notified
via the skip message which is logged. The downstream fill (PaperBroker) acts
as the last safety gate.

### `--bootstrap-price` is dev-only scaffolding
`_bootstrap_price_row` is called only from `scripts/dev_push_signal.py`.
Production code paths (`daily_run`, `process_entries`, `approvals`, `lifecycle`)
carry no `if DEV_MODE` branches. The bootstrap row is overwritten by the next
real EOD sync — no manual cleanup needed.

## 9. Invariants (14 total in `tests/invariants/test_semantic_invariants.py`)

| Family | What it guards |
|---|---|
| Cross-layer semantic | Same concept read from two layers uses same source column |
| Producer-consumer plumbing | Producer computes correctly; consumer doesn't silently drop |
| Configuration / secrets | Two code paths agree on same env var name; no token in tracebacks |
| Run-ledger | `run_id` unique; marker ↔ history consistent |
| **Telegram queue isolation** (v3.7 new) | Pre-startup messages cannot influence signal state |
| **Drift check symmetry** (v3.7 new) | All "cannot verify" exits in `_check_atr_drift` are permissive |

Rule: after adding any new feature that touches two layers, ask whether an
invariant can be added to nail the cross-layer contract.
