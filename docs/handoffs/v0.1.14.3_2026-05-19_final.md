### Bug Fixes Committed

**telegram_send_failed 400 (root cause resolved)**
- Cause: `send_message` default `parse_mode="Markdown"`. Position IDs like
  `pos_594cb3976e68` contain `_` which Telegram Markdown v1 treats as italic
  marker. Unpaired `_` → 400 Bad Request.
- Fix: `send_message` default changed to `parse_mode=None`. Only
  `push_entry_request` and `push_exit_notification` pass explicit
  `parse_mode="Markdown"` (they use *bold* and `code` formatting).
- File: `communication/telegram/bot.py`, `communication/telegram/sender.py`
- Commit: fix: telegram_send_failed 400 — default parse_mode=None

**Bot token redaction in logs**
- Cause: `logger.warning("telegram_send_failed", error=str(e))` — `str(e)`
  on a `requests.HTTPError` includes the full request URL containing the
  bot token.
- Fix: changed to `error=type(e).__name__` — logs error class only.
- Existing log entry manually redacted with sed.
- File: `communication/telegram/bot.py`
- Commit: fix: redact bot token from telegram_send_failed log
