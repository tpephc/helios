## 2. Replay Engine — v0.2.3 (DQ Clean)

**Evolution:** v0.1.0 → v0.2.0 → v0.2.1 → v0.2.2 → v0.2.3

### v0.2.3 Final Features

- **T+1 adj_open** for both entry AND exit (symmetric, conservative)
- **CA gap quarantine:** per-STOCK dates (not global market next_date); force-close
  at prior day's close; `exit_reason = corporate_action_quarantine`
- **Disaster stop:** -25% hard cap; `exit_reason = disaster_stop`
- **Regime lagged 1 day:** `regime[T-1]` matching production (confirmed: 1220/1221
  regime rows computed next day)

- **Hard DQ assertion:** `gross_return_pct < -50%` must be quarantined
- **Exit taxonomy:** `corporate_action_quarantine / disaster_stop / regime_exit /
  trailing_stop / time_stop / end_of_panel`

## 3. Engineering Fixes — Paper-Trading Pipeline

### 3a. Pre-Trade Guard Relaxation (commit a442dc7)

**Problem:** `sim_relaxed()` had daily_orders=3, order_notional=1M — blocked 2/7 orders.

**Fix:**
- `max_daily_orders`: 3 → 20
- `max_order_notional`: 1M → 5M
- `max_daily_notional`: 3M → 15M
- `LiveBroker.__init__`: auto-selects `sim_relaxed()` when `is_simulation=True`

### 3b. Auto-Approve Pipeline (commit db5e1be)

**Problem:** Paper-trading required Telegram approval → Shioaji sim (which had timing bugs).

**Fix — `process_entries.py` v0.1.19:**
- `generate_pending_signals` gains `auto_approve: bool` parameter
- `_auto_approve_and_fill`: getattr resolves breakout (.stock_id) vs pullback (.symbol)
- `main()`: `--account` replaces hardcoded `philip_sim` (4 sites)
- `--auto-approve` hard-blocked for non-paper/sim accounts
- Pullback CLI path now calls `_auto_approve_and_fill`
- Duplicate guard includes `AUTO_APPROVED` status
- `account_id` default removed (explicit required, raises ValueError)

**Fix — `daily_run.py`:**
- `--auto-approve` flag, passed to `generate_pending_signals`
- Step 8 (Shioaji queue) skipped when auto-approve

### 3c. Lot Type Support (commit 3ce2d04)

**Problem:** Orders table CHECK constraint hardcoded `filled_shares = requested_lots × 1000`
(Common lot only). PaperBroker used 1-share resolution → constraint violation.

**Fix — Schema migration (`migrate_orders_lot_type.py`):**
- Added `order_lot_type VARCHAR DEFAULT 'COMMON' NOT NULL`
- CHECK constraint: COMMON → `filled_shares = requested_lots × 1000`;
  ODD → `filled_shares = requested_lots`
- Migration drops existing 17 orders (clean slate)

**Fix — `paper_broker.py`:**
- Auto-detect: `raw_shares >= 1000` → COMMON (round to lot boundary);
  `< 1000` → ODD (exact shares)
- `_record_order`: accepts `order_lot_type`, `requested_qty`, `filled_shares` separately

**LiveBroker impact:** None. `order_lot_type DEFAULT 'COMMON'` handles existing
INSERT statements that don't specify the column.
